# OneDesk — 12-month improvement roadmap (Oct 2026 → Oct 2027)

_Prepared 2026-10-14 from a code read-through of the backend, frontend, infra and docs. Companion to the original build roadmap in `ROADMAP.md`._

## Context
OneDesk (`ticket-proper-portal`) is a multi-tenant ITSM helpdesk: Django 5 + DRF backend
(17 `itsm_*` apps, schema-per-org via django-tenants), Next.js 14 agent workspace +
self-service portal, one APScheduler worker, Postgres 16, Docker Compose behind the
onemedehr-nginx edge at ohd.1learn.ai. Live tenants: onedesk/acme, gridcrest, onemed.

The user asked for a read-through of features/workflow and a 1-year improvement roadmap
with quick wins and a longer-term plan. This document is that roadmap. No code changes.

**Assumptions** (adjust if wrong): OneDesk is sold to several client orgs (SaaS-style),
the team is small (1–3 engineers), and the near-term goal is "fewer support calls, more
self-service, nothing embarrassing in a security review."

## 1. What exists today (verified in code)

**Core ticketing** — tickets with P1–P4 priority derived from Impact×Urgency matrix per
project; ITIL incident/problem fields (major incident, resolution code, root cause,
workaround); EAV custom fields (14 types incl. cascading lists, drag-drop layout designer);
typed links (relates/blocks/duplicates/causes); watchers; attachments; public vs internal
comments; canned responses with `/shortcut`; ticket templates (backend only); move between
projects with number alias; full per-ticket activity log; print sheet.

**Workflow engine** — statuses/transitions with conditions (role, group, assignee,
field, approval), field-condition validators, transition screens, post-functions
(auto-assign 5 strategies, set priority, SLA start/stop/pause, request approval), reopen
rules; "create starter workflow" one-click. Editor is form-based, not a visual canvas.

**SLA** — business calendars + holidays, first-response/resolution/assignment metrics per
priority, pause statuses, breach sweep each minute, escalation rules (notify / reassign /
raise priority). Agent-facing SLA bars in queue + confetti on SLA wins.

**Intake channels** — agent form, portal request form, email (IMAP/POP, Google + M365
OAuth2, threading, loop/auto-reply guards, keyword routing to projects, reopen policy,
per-helpdesk SMTP), `source=api/phone` enums exist but no public API tokens.

**Approvals** — sequential/parallel stages, approver = user/role/group/requestor's manager,
pending-approval badges, hard-blocks transitions while pending.

**Portal** — create request, My Requests (comment, attach, reopen), KB search/read, approvals,
CSAT/NPS feedback. Catalog routes exist but are hidden ("deferred").

**Knowledge base** — categories, draft/publish, portal vs internal visibility, tags.

**Reporting** — 13 UI report types / 19 backend reports, CSV + XLSX export (frozen header
xlsx built, not deployed); interactive drill-down dashboard with KPIs/donuts/trend/aging.

**Admin** — module RBAC (106 perms, 18 modules), Microsoft Entra SSO, branding (name/logo/
contact), user attributes, helpdesks, platform console for org provisioning.

**Platform** — JWT auth with tenant claim, dark mode, decent a11y (axe tests), 15s/60s polling
for live-ish refresh, ~536 backend tests, 2 Playwright specs (stale: pre-`/t/[org]` routes).

### Workflow as a requester / agent experiences it
```
Requester: portal form or email ──► ticket created (routing rule / email keyword → project+group)
Agent:     queue (saved views, cf columns, SLA bars) ──► open ticket ──► inline edit / transition
           ├─ approval gate (blocks until approved)       ├─ SLA timers pause on configured statuses
           ├─ public reply / internal note / canned       ├─ escalation on % of SLA consumed
           └─ resolve ──► survey email ──► CSAT report      └─ close / reopen (rule-bound)
Supervisor: dashboard drill-down ──► reports export ──► settings (fields, workflow, SLA, routing)
```

## 2. Gaps that matter most (ranked)

_Implementation plan for gaps 1–5: `PHASE0_IMPLEMENTATION_PLAN.md`._

| # | Gap | Why it matters | Evidence |
|---|-----|----------------|----------|
| 1 | **Attachments are publicly downloadable** — nginx serves `/media/` with no auth, no tenant prefix | Data-leak across tenants; fails any security review | `nginx/default.prod.conf:48`, `itsm_attachments/ticket/<uuid>/` |
| 2 | **No rate limiting, no lockout, no MFA, logout doesn't revoke JWT** (blacklist app absent) | Brute-force + stolen-token exposure | `core/settings.py` (no THROTTLE), simplejwt config |
| 3 | **Prod runs uncommitted code; no CI; e2e suite is stale** | Every deploy is hand-done and unreproducible; regressions ship silently | 19 dirty files, no `.github/`, `e2e/*.spec.ts` hit `/login` not `/t/[org]/login` |
| 4 | **Agents have no bulk actions UI, no @mentions UI, no live refresh on ticket detail** | Backend already supports `bulk` + `MentionRecord`; two agents overwrite each other | `tickets/views.py` bulk action; `ticket-detail.tsx` has no poll |
| 5 | **Single scheduler process, in-process cache, no observability** | SLA sweeps/email polls stop silently if the container dies; nobody knows | `ticketprod-scheduler`, LocMem cache, no LOGGING/Sentry |
| 6 | **Search is `icontains` only** | KB and ticket search degrade past a few thousand rows | no SearchVector/pg_trgm |
| 7 | **No automation rules engine** (only workflow post-functions + routing + SLA escalation) | Auto-close resolved after N days, nudges, auto-tagging all need code today | — |
| 8 | **Audit log is ticket-only; no admin/security audit; no export** | Compliance asks ("who changed this role?") can't be answered | `itsm_core/models/audit.py` |
| 9 | Portal catalog hidden, no KB deflection on create, no portal notifications | Self-service rate stays low → more agent load | `portal-shell.tsx:17` |
| 10 | No tenant plan/seat/usage metering | Can't bill or cap usage per client | `tenants.Client` has name + is_active only |

Smaller but real: zero tests for approvals/catalog/knowledge/field-engine/tenant isolation;
no `error.tsx`/`loading.tsx`/`not-found.tsx`; no forgot-password; no i18n; `DEBUG` defaults
True in code (prod env sets False, fine, but flip the default).

## 3. Roadmap

Sizing: **S** ≤ 3 days · **M** ≤ 2 weeks · **L** ≤ 6 weeks. Each quarter has a theme and
one measurable outcome. Quick wins are deliberately front-loaded.

### Phase 0 — Quick wins (next 4–6 weeks, Oct–Nov 2026)
Mostly ships what already exists in the backend or is a config/plumbing fix.

| Item | Size | Notes |
|------|------|-------|
| **Lock down `/media/`**: nginx `internal` + Django `X-Accel-Redirect` view that checks ticket permission and tenant; put tenant slug in upload path | S–M | Highest-risk fix. Serve via `/api/v1/t/<org>/itsm/attachments/<id>/download/` |
| **Commit the working tree, tag `v2026.10`**, add deploy script that builds+tags images per release | S | Ends "prod = uncommitted" state. Use existing `scripts/backup-db.sh` as pre-step |
| **GitHub Actions CI**: backend tests on throwaway Postgres (recipe in memory `ticketprod-running-tests`), `tsc` + `next build`, `makemigrations --check` | S–M | Blocks merges on red |
| **DRF throttling + login lockout** (`AnonRateThrottle` on login/refresh/portal intake; `django-axes` or simple cache counter) and nginx `limit_req` on `/api/.*auth` | S | |
| **Enable simplejwt blacklist app** so logout/password-change revokes refresh tokens | S | One migration ×4 schemas |
| ~~Ship the frozen-header xlsx + sticky queue header~~ | — | Done: deployed 2026-10-15 |
| **Bulk actions bar in queue** (select rows → assign / priority / watch / delete) wired to existing `POST tickets/bulk/`; add `transition` to the bulk endpoint | M | Biggest agent time-saver for the cost |
| **Ticket-detail live poll + stale-write guard**: reuse `use-live-poll.ts`; send `updated_at` as `If-Unmodified-Since`-style check on PATCH → 409 + "reload" toast | S–M | Stops silent overwrites |
| **@mentions in composer**: Tiptap mention extension → existing `MentionRecord` + `Mentioned` notification event | M | Backend already there |
| **Apply ticket template from New-ticket form** (backend `apply-template` exists) | S | |
| **`error.tsx` / `not-found.tsx` / `loading.tsx`** at `t/[org]` level; forgot-password flow (email token) | S | |
| **Structured logging + Sentry (or GlitchTip) + scheduler heartbeat** (`healthz` reports last SLA sweep / email poll timestamp per job; alert if > 5 min) | S–M | Turns silent failures into pages |
| **Flip `DEBUG`/`SECRET_KEY` defaults to fail-closed** (raise if unset outside tests) | S | |
| Fix stale Playwright suite (org-prefixed routes, namespaced token keys, add to devDependencies, `npm test`) and run in CI | M | |

**Outcome metric:** zero public media URLs; CI green on every merge; agent bulk-update used weekly.

### Q1 (Dec 2026 – Feb 2027) — "Agent velocity & trust"
Theme: make the agent workspace faster than email, and make the platform observable.

| Item | Size |
|------|------|
| **Command palette (⌘K)**: jump to ticket by number, project, settings page; global ticket/KB search (uses PG full-text below) | M |
| **Postgres full-text search** (`SearchVector` + GIN on summary/description_text/comments; `pg_trgm` for ticket numbers & KB) replacing `icontains`; same index powers portal KB search | M |
| **Keyboard shortcuts** (j/k navigate, a assign, c comment, t transition, ? help) | S–M |
| **Comment edit/delete (own, time-boxed) + "pin internal note"** | S |
| **Merge duplicate tickets** (keep primary, move comments/watchers/attachments, link `duplicates`, close secondary, alias number) and **clone** | M |
| **Automation rules engine v1** (`itsm_automation` app): trigger (ticket created / updated / status changed / time-based nightly) → conditions (reuse `query_builder` JSON) → actions (set field, assign, add comment/canned, notify, transition, add watcher). First shipped rules: auto-close Resolved after N days, "no agent reply in X business hours" nudge, auto-tag by keyword | L |
| **Scheduler hardening**: per-job `max_instances`, per-tenant try/except with job-level metrics; move cache to Redis (shared across gunicorn workers; prerequisite for push + locks) | M |
| **Admin/security audit log** (login, role change, SSO/mailbox config, user activate/deactivate, exports) + CSV export + 1-year retention | M |
| **Tests**: approvals, catalog, knowledge, field engine, cross-tenant isolation (login org A, hit org B → 401/404) | M |

**Outcome metric:** median "time to first agent action" on new tickets down 30%; p95 queue API < 300 ms at 50k tickets.

## 4. Suggested sequencing & dependencies
```
Phase 0 (security + CI + bulk/mentions) ──► Q1 Redis + FTS + automation ──► Q2 SSE, deflection, catalog
                                                       │                           │
                                                       └──► Q3 webhooks → Teams/Slack; API tokens
                                                                           └──► Q4 queue/worker tier, metering, AI
```
- Redis (Q1) unlocks SSE (Q2), distributed locks, and Celery (Q4).
- Full-text search (Q1) unlocks KB deflection and ⌘K search (Q1/Q2).
- Automation engine (Q1) is reused by CSAT follow-up (Q2), OOO reassignment (Q3), retention (Q4).
- Webhooks (Q3) are the base for Teams/Slack and later Zapier; don't build chat integrations first.
