GridCrest · OneDesk setup guide

Connecting Microsoft 365 to your helpdesk

A plain-language, click-by-click guide to two setups: turning your support inbox into tickets, and letting your team sign in with their Microsoft account. No IT background needed — just follow the numbered steps.

Org GridCrest Time ~25 minutes You do this once

The whole idea in one picture

Microsoft won't let another website (OneDesk) touch your email or your sign-ins until you formally introduce them. That introduction is called registering an app. You do it once inside Microsoft, which hands you three code-like values. You paste those three values into OneDesk, and the two systems are connected.

One app covers both jobsYou do not need to do everything twice. You create a single app in Microsoft and reuse the same three values for both the mailbox and the sign-in screens. The only per-job difference is one web address you add and which permissions you tick — both are spelled out below.

Before you startWhat you'll need in front of you

Gather these first. If you don't have the first one, ask whoever manages your company's Microsoft 365 / email — they can either give you access or sit with you for ten minutes.

  • A Microsoft 365 admin account for GridCrest — one that's allowed to register apps. In Microsoft this role is usually called Global Administrator or Application Administrator.
  • The email address you want support mail to arrive at (for example your shared support@… mailbox), and the ability to sign into it.
  • Access to the two OneDesk screens you'll paste values into — you already have these open. We'll call them the Mailbox screen and the Sign-in (SSO) screen.
  • A safe place to temporarily note down three values — a password manager or a sticky note you'll shred. One of them is a secret.

Part 1 — inside MicrosoftRegister the app & collect your three values

This whole part happens on Microsoft's website, not on OneDesk. Take it slowly; every click is listed. By the end you'll have copied down three values and granted permission.

  1. Open the Microsoft admin center and sign in

    In your browser go to entra.microsoft.com and sign in with your admin account. This is Microsoft's control panel for identity — the same place whether you call it Entra or Azure Active Directory.

  2. Go to “App registrations”

    In the left-hand menu open Applications ▸ App registrations. If you can't find the menu, type “App registrations” into the search bar at the top and click the result.

  3. Create a new registration

    Click + New registration. Fill the form in:

    • Name: type something you'll recognise later, e.g. OneDesk – GridCrest. This is just a label; it's only seen by admins.

    • Supported account types: choose “Accounts in this organizational directory only (Single tenant)” — the first option. This keeps it locked to GridCrest only.

    • Redirect URI: leave it blank for now — we add these in the next step. Click Register.

  4. Copy your first two values

    You now land on the app's Overview page. Two of your three values are right here. Copy each one somewhere safe:

    • Application (client) ID — a long code like 983a3980-d6a4-47c2-…

    • Directory (tenant) ID — another long code like 80f988eb-77ff-48e7-…

    i

    These two are not secret — they're more like an account number. It's fine to keep them in a normal note. The third value, coming up, is the sensitive one.

  5. Tell the app where OneDesk lives (add two web addresses)

    In the app's left menu click Manage ▸ Authentication. Click “+ Add a platform”, choose “Web”, and paste the first address below into the box, then click Configure. After that, use “Add URI” to add the second one. Finally click Save.

    Web address #1 — for the mailbox
    https://onedesk.1learn.ai/api/v1/t/gridcrest/itsm/email/oauth/callback/
    Web address #2 — for Microsoft sign-in
    https://onedesk.1learn.ai/api/v1/t/gridcrest/itsm/auth/sso/microsoft/callback/
    !

    Copy these exactlyThey must match character-for-character, including the slash / at the very end. Use the Copy button rather than typing them by hand. A single wrong letter is the most common reason setup fails.

  6. Create your third value — the client secret

    In the left menu click Manage ▸ Certificates & secrets. Under Client secrets click “+ New client secret”. Give it a description (e.g. OneDesk), pick the longest expiry offered (usually 24 months), and click Add.

    !

    Copy the “Value”, and do it right nowA row appears with two columns — Value and Secret ID. Copy the one under Value (it's your third value). Do it immediately: the moment you leave this page, Microsoft hides it forever and you'd have to make a new one. Do not copy the “Secret ID” — that's the wrong one.

    i

    Put a reminder in your calendarBecause you chose a 24-month expiry, this secret will stop working on that date and email + sign-in will quietly break. Set a calendar reminder a couple of weeks before to repeat step 6 and paste the fresh value in.

  7. Grant the permissions the two jobs need

    In the left menu click Manage ▸ API permissions. You'll add a few permissions, then approve them. Click “+ Add a permission” each time.

    For Microsoft sign-in — choose Microsoft Graph ▸ Delegated permissions, then search for and tick these:

    openidprofileemailoffline_access

    For the mailbox — choose “APIs my organization uses”, search “Office 365 Exchange Online”, open Delegated permissions, and tick these:

    IMAP.AccessAsUser.AllSMTP.Send

    When they're all listed, click “✓ Grant admin consent for GridCrest” and confirm. Each row should then show a green “Granted” tick.

    ✓

    Microsoft side is doneYou should now have three things written down: the Application (client) ID, the Directory (tenant) ID, and the secret Value. Keep them handy for Part 2.

Part 2 — inside OneDesk · AConnect the mailbox (email → tickets)

Now switch to OneDesk. This is the “Edit mailbox” panel. Once connected, emails sent to your support address automatically become tickets, and replies go back out from that same address.

Screen
onedesk.1learn.ai/t/gridcrest/agent/w/IT/settings/email → Edit mailbox → “Connection” tab

  1. Paste the three values

    On the Connection tab, fill the boxes using the values you collected in Part 1:

    Box on screenWhat to paste
    Client IDYour Application (client) ID
    Directory (tenant) IDYour Directory (tenant) ID
    Client secretYour secret Value (leave blank only if keeping an existing one)

  2. Save first, then connect

    Click Save changes. The screen even reminds you: “Save any credential changes before connecting.” Only after saving, click “Reconnect mailbox”.

  3. Sign in as the support mailbox

    A Microsoft sign-in window pops up. Sign in as the actual mailbox account whose email should become tickets (e.g. your support@… address) and click Accept on the permission prompt. This is what links OneDesk to that specific inbox.

    !

    Use the right account hereWhichever account you sign in with is the mailbox that gets turned into tickets. If you accidentally sign in as yourself, your personal mail would be pulled in instead — so double-check the address.

  4. Test it

    Back on the Connection tab, click “Test inbound connection”. A success message confirms OneDesk can read the inbox. The green “Connected” badge at the top right means you're done. (The other tabs — Routing, Outbound, Field Mapping — are optional fine-tuning you can leave at their defaults for now.)

Part 2 — inside OneDesk · BTurn on Microsoft sign-in (SSO)

This lets your team log into OneDesk with their existing Microsoft account instead of a separate password. It uses the same app and the same three values you already have.

Screen
onedesk.1learn.ai/t/gridcrest/agent/admin/sso

  1. Confirm the redirect URI matches

    This screen shows a “Redirect URI (add this to your Entra app)” box. It should be the same sign-in address you already added back in Part 1, step 5 — no action needed if it matches. (For reference, it's the one ending in /auth/sso/microsoft/callback/.)

  2. Paste the three values

    Box on screenWhat to paste
    Application (client) IDYour Application (client) ID
    Directory (tenant) IDYour Directory (tenant) ID
    Client secretYour secret Value — use the Value, not the Secret ID
    i

    The screen notes the secret is stored encrypted and never shown again — so if you ever forget it later, you make a fresh one in Microsoft rather than trying to read the old one.

  3. Set the two optional choices

    • Auto-create first-time users: turn this on if you want anyone with a valid GridCrest Microsoft account to get a OneDesk account automatically the first time they sign in.

    • Allowed email domains: optionally list your domains (e.g. gridcrest.com) so only people with those addresses can sign in this way.

  4. Flip the switch on and save

    Turn on the Enable Microsoft sign-in toggle and click Save. Then sign out and try the “Sign in with Microsoft” button on the GridCrest login page to confirm it works.

    ✓

    All setEmails now flow in as tickets, and your team can sign in with Microsoft. Both share the one app you registered — nothing else to maintain except that secret-expiry reminder.

If something goes wrongQuick fixes for the usual snags

What you seeMost likely cause & fix
“Redirect URI mismatch” errorThe web address in Microsoft doesn't exactly match. Re-copy it from Part 1 step 5 — watch the trailing /.
Secret / password rejectedYou probably pasted the Secret ID instead of the Value, or the secret has expired. Make a new secret and paste its Value.
“Need admin approval” / consentGo back to API permissions and click Grant admin consent for GridCrest. You must be signed in as an admin.
Mailbox test failsMake sure you clicked Save before Reconnect, and that you signed in as the support mailbox — not your own account.
Worked before, suddenly stoppedThe client secret likely hit its expiry date. Repeat Part 1 step 6 and paste the new Value into both screens.

Plain-English glossaryThe unfamiliar words, decoded

Microsoft Entra / Azure AD
Microsoft's control panel for accounts and sign-ins. “Entra” is the newer name for what used to be “Azure Active Directory” — same thing.
App registration
A formal introduction that tells Microsoft “this outside website (OneDesk) is allowed to work with our accounts and email.”
Client ID
The app's public ID number. Not secret — like an account number.
Directory (tenant) ID
Your company's unique ID inside Microsoft. Also not secret.
Client secret
The app's password. This one is sensitive — treat it like a password and never share it. It expires and must be renewed.
Redirect URI
The exact web address Microsoft is allowed to send people back to after they sign in. Must match exactly.
Permissions / consent
The specific things the app is allowed to do (read the inbox, send mail, confirm who someone is). “Granting consent” is you approving them.
SSO (Single Sign-On)
Signing into OneDesk with your existing Microsoft account, so there's no separate password to remember.
